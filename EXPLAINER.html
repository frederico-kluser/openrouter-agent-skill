Material do usuário → verificação claim-a-claim

O material de ajuda fornecido (arquitetura avançada de roteamento) foi verificado item a item contra os docs oficiais e o OpenAPI spec. 15 problemas factuais encontrados e corrigidos na Onda 1, mais 1 divergência corrigida na Onda 3 (spec ao vivo).

CORRIGIDO (não ensinar como válido)
  • provider_id → o campo real é tag
  • q8_0 → não existe no enum (int4..fp32)
  • X-OpenRouter-App → não existe (attribution via HTTP-Referer/X-Title)
  • pdf-input → plugin real é file-parser
  • effort: "min" → minimal; price_source: "completion" → prompt|weighted_avg
  • prompt_cache_options.mode: "simple" → só explicit
  • weights, transforms, cost_tier top-level → não existem
  • "500+ modelos" → 411 (verificado ao vivo)
CONFIRMADO
  • Balanceamento estocástico 1/p² com janela de 30s
  • allow_fallbacks default true; zero-completion insurance
  • Variantes :nitro/:floor e sort exacto
  • max_price estrito vs preferred_* como preferência
  • Sticky routing (session_id, 10 min), response caching (TTL 300s)
  • BYOK (5% markup, isenções US$25k/US$200k)
  • Plugin response-healing; auto-router com cost_tier por bandas
Fato corrigido na Onda 3 pelo spec ao vivo

ANTES: GOTCHA #13 afirmava que reasoning_effort top-level não inclui max. DEPOIS: spot-check no openapi.yaml ao vivo (2026-08-14) mostrou enum idêntico ao de reasoning.effort (inclui max) — corrigido em SKILL.md:168, references/api.md:232 e no doc de pesquisa.

O que cada mudança significa para quem usa o deep-orchestrator:

Busca Brave integrada — sub-agentes pesquisam na web direto do terminal (curl + API Brave), sem depender de outras ferramentas.

Busca padronizada — prompts de pesquisa consistentes entre sub-agentes (search-prompts.md).
De-para visível — toda execução termina com um EXPLAINER.html legível (este documento).
Processo documentado — ondas ilimitadas e o novo fluxo registrados no SKILL.md.

Premissas inferidas sem perguntar

O orquestrador opera em autonomia total: nenhuma pergunta foi feita ao usuário. Toda premissa assumida fica registrada aqui — para revisão e reprodutibilidade.

  • Idioma: skill em pt-BR com termos técnicos em inglês (perfil do usuário).
  • Estrutura: SKILL.md na RAIZ do repo — pré-condição do symlink global (o link aponta para o diretório que contém SKILL.md).
  • SDKs oficiais (@openrouter/sdk, @openrouter/agent): citados apenas por nome + link (proibido inventar API não pesquisada); caminho primário = SDK OpenAI com base_url.
  • Testes sem custo: CLI e smoke tests operam em dry-run sem chave (nenhum crédito gasto; --live opcional).
  • GitHub: repo público "openrouter-agent-skill" no perfil do usuário; About (description + tópicos) aplicado via gh repo edit no COMMIT-FINAL.
  • Symlinks globais: 3 pontos de consumo (Claude Code, opencode/Codex/Cursor/Gemini, variante claude-deepseek), padrão deep-orchestrator (~/Projects → dirs de skills).
  • GOTCHAS datados preservados: os 21 gotchas e "411 modelos em 2026-08-14" são verificados e datados — a anti-checklist não os trata como erro.
  • Ordem de merge: skill-core → skill-tooling → repo-readme (README referencia arquivos das branches irmãs).
  • Revisão adversarial: 15 + 1 + 2 problemas factuais reais encontrados e corrigidos antes de qualquer merge (nunca merge sem gate).
